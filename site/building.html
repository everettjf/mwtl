Installation guide

From zero to a native window.

Choose the workflow you already use. Every path builds the same C++20 x64 library and links the exported mwtl::mwtl target.

OSWindows 10 1809+ or Windows 11
ToolchainMSVC, Windows SDK, C++ ATL
LanguageC++20, x64
BuildCMake 3.21+
Recommended

CMake project

Fetch a pinned release directly from your application. mwtl fetches its pinned WTL 10.01 and WIL dependencies and propagates the required include paths, libraries, and C++20 setting.

# CMakeLists.txt
cmake_minimum_required(VERSION 3.21)
project(my_app LANGUAGES CXX)

include(FetchContent)
FetchContent_Declare(mwtl
  GIT_REPOSITORY https://github.com/everettjf/mwtl.git
  GIT_TAG main
  GIT_SHALLOW TRUE)
FetchContent_MakeAvailable(mwtl)

add_executable(my_app WIN32 main.cpp)
target_link_libraries(my_app PRIVATE mwtl::mwtl)
cmake -S . -B build -G "Visual Studio 18 2026" -A x64
cmake --build build --config Debug
Visual Studio 2022: replace the generator with Visual Studio 17 2022. The library supports VS 2022 or newer.
Reusable installation

Install once, consume with find_package

git clone --depth 1 https://github.com/everettjf/mwtl.git
cmake -S mwtl -B mwtl-build -G "Visual Studio 18 2026" -A x64
cmake --build mwtl-build --config Release
cmake --install mwtl-build --config Release --prefix C:/deps/mwtl
# consumer CMakeLists.txt
find_package(mwtl CONFIG REQUIRED)
add_executable(my_app WIN32 main.cpp)
target_link_libraries(my_app PRIVATE mwtl::mwtl)

# configure
cmake -S . -B build -A x64 -DCMAKE_PREFIX_PATH=C:/deps/mwtl
IDE workflow

Visual Studio

Open the folder containing your CMake project with File → Open → Folder. Visual Studio detects CMakeLists.txt, configures CMake, and exposes my_app.exe in the startup-item selector.

  1. Install the Desktop development with C++ workload.
  2. In Individual components, enable C++ ATL for the current MSVC toolset and a Windows 10/11 SDK.
  3. Select an x64-Debug configuration; x86 and ARM64 are intentionally rejected.
  4. Choose the application target and press F5.

For an existing CMake-based Visual Studio solution, add the FetchContent block above. No manual include directory, library directory, or preprocessor configuration is required.

Editor workflow

VS Code

Install Microsoft’s C/C++ and CMake Tools extensions, then open the project folder from an x64 Native Tools command prompt or let CMake Tools discover the installed Visual Studio kit.

  1. Run CMake: Select a Kit and choose an amd64 MSVC kit.
  2. Run CMake: Configure.
  3. Choose Debug on the status bar and run CMake: Build.
  4. Select my_app as the launch target and run CMake: Debug.
// .vscode/settings.json
{
  "cmake.generator": "Visual Studio 18 2026",
  "cmake.configureArgs": ["-A", "x64"],
  "cmake.buildDirectory": "${workspaceFolder}/build"
}

On Visual Studio 2022, use Visual Studio 17 2022. CMake Tools supplies IntelliSense from CMake’s compile model, so do not duplicate mwtl include paths in c_cpp_properties.json.

Application code

Your first mwtl window

#include <mwtl/mwtl.h>

class MainWindow final : public mwtl::WindowBase {
public:
    void BuildUI() override {
        SetTitle(L"My app");
        mwtl::ControlHost ui{*this};
        ui.Add(message_, L"Hello from mwtl");
        ui.Add(close_, L"Close");
        SetLayout(mwtl::Column().Margin(24.0_dip).Gap(12.0_dip)
            .Add(message_, mwtl::Auto())
            .Add(close_, mwtl::Fixed(36.0_dip)));
    }

    mwtl::EventResult OnCommand(const mwtl::CommandEvent& event) override {
        if (event.IsClicked(close_)) { Close(); return mwtl::EventResult::Handled(); }
        return mwtl::EventResult::Propagate();
    }
private:
    mwtl::Label message_;
    mwtl::Button close_;
};

int WINAPI wWinMain(HINSTANCE instance, HINSTANCE, PWSTR, int show) {
    return mwtl::RunApplication<MainWindow>(instance, show);
}

Controlled environments

Offline dependencies

cmake -S . -B build -A x64 \
  -DMWTL_WTL_SOURCE_DIR=C:/deps/wtl \
  -DMWTL_WIL_SOURCE_DIR=C:/deps/wil

You can also define WTL::WTL and WIL::WIL before adding mwtl. The build never silently selects an unidentified system copy.
